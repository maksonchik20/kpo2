# ПОС

Python 3.9+. Команды из папки проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pos
python -m pos --demo
python -m pytest -q
```

В Windows вместо `source` используйте `.venv\Scripts\activate.bat` (cmd) или `.venv\Scripts\Activate.ps1` (PowerShell).

Ведомость сохраняется после каждого изменения в `data/gradebook.json`. Другой путь: `--data my-course.json`. Экспорт из меню записывается в `exports/totals.csv`; путь задаётся через `--export result.csv`. Числа можно вводить с точкой или запятой. Повторная оценка по той же паре студент/критерий заменяет предыдущую, отмена удаляет её.

Демо работает с отдельной ведомостью в памяти: добавляет двух студентов и два критерия, выставляет, исправляет и отменяет оценки, показывает отказы и выгружает `exports/demo-totals.csv`. Сохранённая ведомость не меняется.

## Расчёт

Итог на шкале 0–10: `10 × Σ(балл / максимум × вес) / Σ(вес)`. Веса положительные; их сумма не обязана быть равна 1. Например, 10/20 с весом 2 и 8/10 с весом 3 дают **6,8**.

- `--mode final` (по умолчанию): пропущенные оценки считаются нулями.
- `--mode current`: предварительный результат, учитываются только оценённые критерии. Выставленный ноль учитывается, отсутствие оценки — нет.

Без критериев итог не определён. Без оценок в текущем режиме тоже выводится «нет данных», в CSV ячейка остаётся пустой. Режим и количество оценённых критериев записываются в экспорт. Округление до сотых выполняется только при выводе, половина округляется вверх. Внутри используется `Decimal`.

В демо итог Анны — **9,00**, Бориса — **2,00**. С `--mode current --demo` у Бориса будет **5,00**, потому что экзамен ещё не оценён.

## Модель и слои

Выбрана **Ports and Adapters**: `adapters → application + ports → domain`. [Контейнер](pos/container.py) собирает зависимости на внешнем уровне; домен не импортирует консоль, файлы или библиотеку DI.

Общая запись файлов и форматирование баллов находятся в [adapters/utils.py](pos/adapters/utils.py). Проверки модели и формула итога остаются в домене.

| Часть | Решение |
| --- | --- |
| [domain.py](pos/domain.py) | Студент (`Student`), критерий (`Criterion`), оценка (`Evaluation`) и итог (`Total`) соответствуют словам предметной области. |
| Entity | `Student` и `Criterion` сравниваются по ID, остальные поля в сравнении не участвуют. |
| Value Object | `Score` — неизменяемый балл, сравнивается по значению. `Evaluation` — неизменяемая запись; исправление заменяет её целиком. |
| Агрегат | `Gradebook` — одна ведомость курса. Только его методы добавляют сущности и меняют оценки. Он не отдаёт изменяемые словари наружу. Модель проверяет диапазон, наличие студента и критерия, уникальность ID. |
| Domain Service | `TotalCalculator` вычисляет результат из рубрикатора и актуальных оценок. Итог отдельно не хранится, поэтому исправления сразу отражаются в следующем расчёте. |
| [application.py](pos/application.py) | Сценарии загружают ведомость, вызывают доменную операцию и сохраняют результат. Экспорт сначала получает свежие итоги. |
| [ports.py](pos/ports.py) | Контракты `GradebookRepository` и `TotalExporter`. |
| [adapters](pos/adapters) | JSON-репозиторий, CSV-экспорт и консоль. Память используется в демо и тестах. Повреждённый JSON отклоняется, а не заменяется пустой ведомостью. Файл обновляется через временный файл и замену после успешной записи. |

Граница агрегата выбрана для одного курса: при загрузке можно проверить все связи сразу. Для нескольких курсов понадобятся отдельные ведомости. Изменение и удаление студентов/критериев пока не добавлены; для оценок есть исправление и отмена.

## Паттерны и DI

- **Фабрика — `EvaluationFactory`**: единая точка создания оценки. Находит студента и критерий в ведомости, создаёт `Score` и проверенную запись. Через неё проходят и ввод, и восстановление JSON. Это простая фабрика.
- **Facade — `PosFacade`**: консоль не координирует репозиторий, расчёт и экспорт сама. Эти действия собраны в сценариях фасада.
- **Strategy — `FinalStrategy` и `CurrentStrategy`**: разные правила для незавершённого оценивания. `TotalCalculator` получает выбранную стратегию через конструктор.

В `dependency-injector` репозиторий — `Singleton`, фасад и калькулятор создаются через `Factory`, стратегию выбирает `Selector`. Подмена репозитория через `container.repository.override(...)` проверяется в [test_container.py](tests/test_container.py). Фасад и домен к контейнеру не обращаются.

[Тесты](tests) проверяют границы баллов, неизвестные ссылки, исправление и отмену, оба режима расчёта, восстановление JSON, сохранность файла при ошибке записи и сквозные сценарии консоли.

Пользователь попросил написать тесты, отрефакторить его код, чтобы он соответсовал стилевым правилам и написать README.
